# 芬太片流程开发方案

日期：2026-11-13。基线：`f7b0e03` / 0.4.8。本轮仅整理方案，未实现或游戏内验收。

范围仅为《Probably Stolen》游戏机制。原生证据见[研究报告](../Research/FantaWorkflow-20261113.md)。旧报告的“两级过滤”已过时，实施以0.4.8单道过滤为准。

## 首阶段范围

玩家手动拆包并将前体液放入搅拌机工作瓶；助手在结束当天处理这一瓶，按实际干湿状态安排后处理与移交，成型仍由玩家操作。自动拆包、仓库取前体、自动成型留待后续。

顺序：只读识别及预检 → 常温稳定剂前处理 → 检查剩余酸碱 → 按当前实际成分补反应物 → 原生控温反应 → 严格完成检查 → 单道过滤及按需净化 → 湿料进蒸发器原生过夜，干料进制剂机。

无挥发液与反应完成是独立条件，不能以干燥、有少量产物或无进度替代完成判定。

## 接入任务

| 2 | BatchPlan.cs、Preflight.cs | 稳定剂阻断改为前处理需求；预算实际来源浓度、杂质、各阶段投料及峰值容量。规划只读，运行分阶段复核。无法可靠预算时明确阻断，不简单删除旧错误提示。 |
| 3 | Workflow.cs、BatchPreparation.cs | 建议新建 FantaPreparation.cs 承担前处理迭代器，复用原生反应。无进度、缺料、容量变化或瓶被移动即停止；完成后根据真实成分重新计算补料。 |
| 4 | BatchPreparation.cs、HeatingControl.cs | 复用控温、关火和目标恢复；区分抑制、缺反应物、整数尾量和真正完成。尾量补料有次数、容量及残余约束，禁止无限重试或大量过投。 |
| 5 | Filtration.cs、Purification.cs | 后处理前统一检查不可过滤/蒸发残余；沿用滤芯优先、棉布备用的单道过滤，不默认重复前置过滤。净化按实际污染决定，移交前再检查残余。 |
| 6 | Distillation.cs、EvaporatorRouting.cs、MachineBottles.cs | 湿料复用配方分工及容量/电力检查；增加当前工作瓶直接交付干料的路径，现有 StageDryEvaporatorBottles 只扫描蒸发器。无挥发液路线免除无必要的蒸发器预检。无接收位置时保留当前瓶。 |
| 7 | InventoryReport.cs、CompositionPanel.cs | 沿用现有布局展示阶段、实际耗料、残余、设备/瓶号及停止原因；报告跟随真正接收瓶。若改布局，先依 DEVELOPMENT 展示预览并确认。 |

## 实施前需要定案

- 残余放行标准：明确检查前体、稳定剂归零；酸碱及还原剂残余需要有明确允许范围。在标准确定前保料并报告，不能把原生允许成型当作流程成功，不静默引入任意纯度阈值。
- 原生调用：根据已有 IL 确认常温阶段入口和伴随反应，保持原生调度语义；不直接写成分模拟产品，不根据孤立公式承诺精确耗料。
- 预算一致性：规划的试剂方向、来源份额、杂质和容量应对应实际分次投料；阶段间刷新真实成分并核对库存变化。
- 失败恢复：预检不改材料；执行失败保留已经发生的原生变化，清理加热器及迭代器并报告瓶位置。重跑从当前成分识别阶段，避免重复投料。

## 建议交付节奏

先交付正确入队、严格完成判定和只读需求展示，明确标注前处理尚未支持；再接入前处理与控温反应；最后补齐干湿分流及完整报告。各阶段保留必要阻断，完成前不宣称完整支持。开始修改功能时再按仓库约定推进 VERSION、CHANGELOG 与使用说明，本轮保持0.4.8。

## 验证要求

按 AGENTS 不新增或运行测试。实现阶段执行 scripts/build.ps1 及原生 ModScanner，检查差异；离线通过不代表游戏内验收。部署、启动游戏与发布依玩家后续指令进行。

玩家验收覆盖：无挥发液前体入队；已有产物但仍受抑制；缺料、不纯来源及容量不足；整数尾量；移瓶、取消和关火恢复；滤芯耗尽接续棉布；湿料无蒸发器、干料无制剂机；重复结束当天、切档、多机队列；原有咖啡因与梦帽菇路线回归。根据实际日志、成分与瓶位置核对，不以预估产量代替验收。
